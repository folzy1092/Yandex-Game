# Offline-прототип FPS (Этап 1) — дизайн

Дата: 2026-08-20
Статус: approved

## Контекст

Проект: браузерный 3D FPS в стиле CS 1.6 для Яндекс Игр, монетизация через рекламу
(fullscreen между матчами, rewarded за бонусы). Полный план (мультиплеер, master
server, серверный браузер, Yandex SDK) описан в `Новый текстовый документ.txt`
в корне проекта — это отдельные под-проекты, которые пойдут следующими этапами.

Этот документ покрывает только первый под-проект: **локальный offline-прототип**
без сети и без Yandex SDK. Цель — доказать core loop (движение + стрельба) на
одной карте, прежде чем вкладываться в сеть и графику.

## Решения

**Движок: Unity (C#) + WebGL.**
Причина: официальный бесплатный курс Яндекса "Создание игры на Unity для
Яндекс Игр" рассчитан на новичков и учит именно программированию + сборке под
их платформу; для Unity есть готовый Yandex Games SDK плагин и множество
FPS-туториалов на русском. Альтернативы из официального списка SDK-плагинов
(Cocos Creator, Construct 3, Defold, TypeScript) хуже подходят: Construct/Defold
преимущественно 2D, чистый TypeScript требует писать 3D-движок с нуля.

**Автор — новичок в геймдеве**, опыта в C#/JS нет. Поэтому везде, где можно,
используются готовые официальные Unity-пакеты вместо кода с нуля.

## Область (in scope)

1. **FPS-контроллер** — Unity Starter Assets (First Person), официальный
   бесплатный пакет. Даёт: WASD-движение, Shift-бег, Space-прыжок, Ctrl-присед,
   mouse look. Не пишем контроллер с нуля.
2. **Оружие — Pistol.** Hitscan (Raycast из камеры при выстреле), не projectile —
   проще и стандартно для пистолета. Ammo-счётчик, reload по клавише R.
3. **Карта — Pool.** Симметричная арена: Blue spawn слева, Red spawn справа,
   бассейн в центре как визуальный фокус/укрытие. Строится через встроенный
   Unity ProBuilder (блокаут стен/платформ, без внешнего 3D-софта) + один
   низкополигональный prop-пак (ящики, лампы, столы) для декора.
4. **HP и смерть.** HP = 100, урон при попадании raycast'а. При HP <= 0 —
   смерть, respawn через N секунд на своём споне (Blue/Red).
5. **UI.** Прицел (crosshair), HP-бар, счётчик патронов. Минимум, без меню.

## Вне области (out of scope на этом этапе)

- Сеть/мультиплеер (Colyseus, WebSocket) — следующий под-проект.
- Yandex Games SDK, реклама, авторизация, сохранения — следующий под-проект.
- Второе и последующие оружия (SMG/Shotgun/Rifle/Sniper).
- Меню серверов, коды комнат, matchmaking.
- Боты/AI-противники — если нужно проверить попадания, использовать
  статичные мишени (dummy targets), не полноценный AI.

## Данные и состояние

Всё состояние — локальное, в памяти Unity-сцены. Нет бэкенда, нет сохранений
между сессиями на этом этапе.

## Производительность

Цель: 60 FPS на среднем школьном ПК, не ниже 30–45 FPS на слабом/интегрированной
графике. Ограничения ради этого: baked lighting, минимум прозрачности и
динамических объектов на карте, low-poly модели, texture atlas.

## Тестирование

Ручное — нет отдельного QA-этапа для прототипа:
- Плейтест в Unity Editor (движение, стрельба, урон, смерть, respawn).
- Собранный WebGL-билд, открытый в Chrome и Яндекс.Браузере — проверка, что
  контролы и стрельба работают так же, как в редакторе.
- Проверка FPS через Unity Stats/Profiler на целевом железе (или ближайшем
  доступном) — сверка с целью 60 / 30–45 FPS выше.

## Критерий готовности этапа

Можно зайти в сцену, побегать по карте Pool, выстрелить из пистолета в мишень
или другого игрока (в редакторе — второй экземпляр камеры/тестовый объект),
увидеть урон и HP-бар, умереть, респавниться на своём споне. WebGL-билд
открывается в браузере и держит целевой FPS.
